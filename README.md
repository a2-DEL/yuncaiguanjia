## 🤔 这是什么

传统财务软件的通病是 **「一套会计界面硬塞给所有人」**——老板看不懂、会计觉得浅、业务部门觉得跟自己没关系。

**云财管家** 在同一套 IndexedDB 账本、同一条 SHA-256 审计链之上，长出三套完全不同的交互视角：

```
┌─────────────────────────────────────────────────┐
│              1 个数据底座（本地 IndexedDB）        │
│   凭证 · 科目 · 报表 · 哈希链审计 · 加密备份       │
└─────────────────────────────────────────────────┘
           ↑              ↑              ↑
   ┌───────┴───────┐ ┌────┴─────┐ ┌──────┴──────┐
   │ 老板驾驶舱    │ │ 财务工作台 │ │ 业务端入口   │
   │ (Boss View)  │ │ (Fin Ops)│ │ (Quick Entry)│
   │ 看结果+预警   │ │ 批 Proposal│ │ 说人话就记账 │
   └───────────────┘ └──────────┘ └─────────────┘
           ↑              ↑              ↑
           └──────────────┼──────────────┘
                    AI Agent 团队
              （6 个数字员工，按岗位分工）
```

## 🏰 护城河与差异化

| 维度 | 金蝶/用友 | 简记/随手记 | 通用 AI 聊天框 | **云财管家** |
|---|---|---|---|---|
| 视角 | 一套会计界面 | 个人记账 | 一个万能框 | **3 层原生角色视图** |
| AI 形态 | 插件按钮 | 无 | 权责模糊 | **6 个岗位化 Agent，权限=岗位职责** |
| AI 必要性 | 可选 | — | 不用就没价值 | **双动力：不用 AI 也是完整财务软件** |
| 数据位置 | 厂商云 | 厂商云 | 厂商云 | **本地 IndexedDB，数据不出设备** |
| 业务协同 | 另买模块 | 无 | 无 | **业务说一句→自动翻译凭证→财务审批** |
| 审计 | 厂商后端 | 无 | 无 | **SHA-256 哈希链，本地可校验** |

**一句话：别人卖的是「给会计用的记账软件，顺便加了点 AI」；你做的是「覆盖老板/财务/业务全员的经营协作系统，AI 是每个人的岗位助理，可开可关」。**

## ✨ 核心功能

### 1. 老板驾驶舱 `/boss`
- 可动用资金 / 本月利润 / 30 天现金最低点 / 毛利率 四大数
- **30 天现金流预测曲线**（线性外推）
- **风险预警面板**（跑道<60 天、逾期应收、税负临界点）
- **What-If 经营沙盘**：涨薪 10% / 客户拖款 30 天 / 打 9 折
- **自然语言问答**："这个月赚了多少？""哪个客户欠最多？"
- 一键导出月度经营简报 PDF

### 2. 岗位化 Agent 团队（6 个数字员工）

| Agent | 岗位 | 权限 | 做什么 |
|---|---|---|---|
| `bookkeeper` | 记账专员 | 可写·待批 | 流水/人话批量生成凭证草稿 |
| `auditor` | 审核主管 | 只读·建议 | 全量凭证扫描，找科目错用/异常 |
| `cashier` | 出纳专员 | 可写·待批 | 银行流水匹配、自动登账 |
| `taxer` | 税务专员 | 只读·建议 | 进销项计税、小规模免税线提醒 |
| `watcher` | 经营参谋 | 只读·建议 | 现金流断裂预警、What-If 诊断 |
| `reporter` | 报表参谋 | 只读·建议 | 经营异常归因、月度简报 |

> **铁律**：Agent 的权限严格对应当岗位人工权限。出纳 Agent 永远不能碰成本核算，审核 Agent 永远不能直接改账——财务内控的不相容职务分离。

### 3. Proposal 人审闸门
AI 不直接改账。所有 Agent 产出的都是 **Proposal（待批提议）**，推到财务工作台：
- ✅ 批准 → 自动生成凭证草稿（借贷平衡校验）
- ❌ 驳回 → 回到 Agent 重跑
- 三档强度：全自动 / 待批（推荐）/ 仅建议

### 4. 说一句就记账 `/quick`
业务端说人话，系统自动翻译成会计分录：

| 你说 | 系统做的凭证 |
|---|---|
| 打车 86 微信付 | 借：交通费 86 / 贷：微信 86 |
| 进货 5000 未付款 | 借：库存商品 5000 / 贷：应付账款 5000 |
| 客户转了 8000 | 借：银行 8000 / 贷：收入 8000 |
| 卖给张三 5000 没收到钱 | 借：应收账款 5000 / 贷：收入 5000 |

### 5. 调度员（每周自动体检）
- 每周自动串起经营参谋→出纳→审核→税务
- 异常自动生成 Proposal 推到老板待办
- 全程留痕在哈希链日志

### 6. 手机端 `/m`
4 Tab：看钱（大卡片）/ 问一句 / 记一笔 / 批待办。PWA 可装到手机桌面。

## 🧱 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 生态成熟，类型安全 |
| 构建 | Vite 5 | 秒级 HMR |
| UI | Ant Design 5 + Tailwind CSS | 企业级组件 + 原子样式 |
| 状态 | Zustand | 轻量，无样板 |
| 数据库 | Dexie (IndexedDB) | **本地优先，零后端，数据隐私** |
| 图表 | Recharts | 财务可视化 |
| 路由 | React Router 6 | 权限路由 |
| AI | OpenAI 兼容协议 | DeepSeek / 豆包 / 通义 / 智谱 / OpenAI 任意切换，**Key 自备** |

**为什么本地优先？** 小微企业最敏感的是财务数据。数据存在用户自己浏览器里，不经过任何服务器——这是对金蝶/用友云的**结构性反驳**。
